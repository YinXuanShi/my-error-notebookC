# 02 - 解方程（二分法）

> PTA 7-6 · 2026-11-04

## 题目

已知函数 `f(x) = cos(2x) · √x - c`（c 为常数），在 `[x1, x2]` 上单调递增或递减。
求方程 `f(x) = 0` 在该区间内的解，保留小数点后四位数字。

**输入格式**：三个浮点数——常数 `c`，区间边界 `x1`、`x2`。保证 `x2 > x1`，`f(x)` 在 `[x1,x2]` 单调，且方程在该区间有唯一解。

**样例**

```
输入：1.0 2.0 3.0
输出：2.6844
```

> ⚠️ 题目配图写的是 `y = cos(2x)/√x`，但从样例反推，**实际函数是 `cos(2x) · √x`（乘法）**。用乘法算 `x=2.6844` 处 `y=1.0000` 正好与 `c=1.0` 的水平线相交；用除法在 `[2,3]` 内无根。

## 我犯的错误

### 错误 1：return 漏分号

```c
return sqrt(x)*cos(2.0*x)-c     // ❌
return sqrt(x)*cos(2.0*x)-c;    // ✅
```

编译报错：`error: expected ';' after return statement`

---

### 错误 2：用未初始化的变量初始化别的变量（致命）

```c
double r = x1;    // ❌ 此时 x1 还没被 scanf 赋值
double l = x2;    // ❌ 同上
scanf(...);       // 现在才读入 x1/x2，但 r/l 已经是垃圾值了
```

编译警告：`variable 'x1' is uninitialized when used here`

**修正**：赋值移到 scanf 之后

```c
scanf("%lf %lf %lf", &c, &x1, &x2);
r = x1;    // ✅
l = x2;
```

**核心规则**：`scanf` 之前不要用还没读入的变量初始化别的变量。顺序永远是：

```
声明 → scanf 读入 → 用读入的值做后续操作
```

---

### 错误 3：二分循环里改 mid 导致区间收缩到错误位置

```c
// ❌ 你的写法
if (q < 0) {
    mid = (mid + r) / 2.0;   // 先把 mid 偏移了
    l = mid;                 // 再把偏移后的 mid 给 l → l 落点不对
}
```

结果：样例输出 `3.0000` 而不是 `2.6844`。

**二分法只改 `l` 或 `r`，绝不要动 `mid`。** mid 每轮循环开头会被 `mid = (l+r)/2.0` 重新计算。

```c
// ✅
if (q < 0) {
    l = mid;
}
```

---

### 错误 4：只用 `f(r)*f(mid)` 判断，端点为根时会丢掉解（隐蔽）

```c
q = f(r, c) * f(mid, c);
if (q < 0) { l = mid; } else { r = mid; }
```

**问题**：当 `f(r)` 恰好为 0（根就在端点）时，`q = 0`，`q < 0` 为假 → 走 else 分支 → 根被丢弃，一路推到 `x2`。

**修正**：分别判断 mid 与两端的关系，并用 `<= 0` 覆盖"mid/端点正好是根"的情况：

```c
if (fl * fm <= 0) {        /* 根在 [l, mid] */
    r = mid;
} else if (fm * fr <= 0) { /* 根在 [mid, r] */
    l = mid;
} else {                   /* 端点情况：保留 |f| 小的一侧 */
    if (fabs(fl) <= fabs(fr)) { l = mid; }
    else                      { r = mid; }
}
```

同时全程记录 `|f|` 最小的点作为兜底答案（`best_x`），即使判断逻辑走到极端分支也不会输出离谱结果。

---

### 错误 5：r / l 命名与实际左右边界相反

我原来的写法里 `r` 是左边界（x1）、`l` 是右边界（x2），与直觉相反。**结果是对的，但很容易在后续修改中写反判断。** 修正为统一 `l` = 左边界、`r` = 右边界。

## 知识点总结

### 1. 二分法求根模板（稳健版）

```c
double l = x1, r = x2;
for (int i = 0; i < 200; i++) {
    mid = (l + r) / 2.0;
    double fl = f(l, c), fm = f(mid, c), fr = f(r, c);

    if (fl * fm <= 0)      r = mid;   /* 根在左半 */
    else if (fm * fr <= 0) l = mid;   /* 根在右半 */
    else {                          /* 端点情况 */
        if (fabs(fl) <= fabs(fr)) l = mid;
        else                      r = mid;
    }
    if (r - l < 1e-14) break;
}
```

**三个要点**：

1. `<= 0` 而不是 `< 0`——把"恰好是根"的情况也纳入正确分支
2. 分别判断两个半区间，不要只用一个乘积
3. 只改 `l` / `r`，不改 `mid`

### 2. 迭代次数

- `double` 区间二分：**100 次足够**（2^-100 ≈ 10^-30，远超 double 的 ~16 位有效精度）
- 实测：第 51 次迭代后 `mid` 就已经停滞（`mid == r` 或 `mid == l`），说明精度已到极限
- 20 次迭代就能稳定输出 `2.6844`，111 次毫无必要但也无害

### 3. 精度已足够

精确根 = `2.6844404909091812`，`%.4f` 输出 `2.6844`，与题目标准答案完全一致，误差 4e-5 < 5e-5。
